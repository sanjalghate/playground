1 · Recommendation

Ship the consequence-first dialog. Keep the plain port as the fallback. Park duplicate-with-undo until someone rules on the brief.

Job: an author needs the same tests pointed at a different environment, on its own cadence — 450 of the sibling suite pairs in the last 90 days are exactly that, making it the most frequent job by a factor of three.

VariationCallWhy
BConsequence-first dialog ★ Ship now Wins the most-frequent job (environment variant): it is the only option where the author cannot miss that the carried schedule is paused, which is the specific harm the PRD names — two suites firing at the same time on one parallel pool. Also the only variation with no friction dimension below the pass mark, and it satisfies the four Design-KB rules that actually bite here (error handling, journey completeness, microcopy, discoverability). It is A plus one content block and debounced validation — the same modal shell, so the delta is small.
AClone-test dialog, as shipped Fallback Reference — lowest-risk floor. Invents nothing: it is CloneTestModal re-pointed at a suite. Ships if B’s extra content block is contested. Costs you prevention: its validation is blur-only and the two consequences read as prose the eye skips.
CDuplicate now, undo after diverges from brief Later Fastest by a wide margin — one click against A’s four — and it is what the Design KB’s own friction rules point at, since duplicating is reversible and undo beats a confirm dialog. But it removes the dialog the PRD explicitly requires, and with no dialog there is nowhere to run FR-4’s pre-create name check. Needs a human ruling before it can be built, plus inline row-rename and an undo-delete path.
How this pick was made
Design KBFed the pick. Present and read — 13 rules. B satisfies error-handling, journey-completeness, content-and-microcopy and discoverability where A and C each miss at least one.
JTBDFed the pick, and it is firm. The most-frequent job came from the PRD’s own 90-day query (450 environment pairs vs 148 browser pairs) — not inferred. This is the usual soft spot in a variations run and here it is actually grounded.
Product KBUnavailable — 2 of 3 sources. No stack-product/lcnc-webapp profile, so every product-specific row grades NA and contributes neither for nor against. The ★ rests on the two sources above.
Decisive open questionIs duplication synchronous or asynchronous? The PRD punts it (“judged developer-side”). If it is async, A’s ported progress-toast pattern becomes load-bearing and B must adopt it too — which narrows the gap between them. It does not flip B over C, but it does change what B has to build.
Open decisions that could change the pick
Sync or asyncUnresolved in the PRD. Both result states are drawn in every variation so the fork stays visible rather than being quietly decided in code.
Does C’s paradigm
get a hearing?		The Design KB says confirmations are for irreversible actions and duplicating a suite is reversible; the PRD says there must be a dialog. Both are legitimate. If the PRD’s author accepts a stated toast as “not silent”, C becomes the strongest option on the two most frequent jobs. This is the single biggest thing that could flip the recommendation.
Permission gate
on the row menu		The ⋮ menu only renders when canUpdateSuite is true, but Duplicate needs create, not update. A user with create-but-not-update sees no menu, so no Duplicate. Every variation inherits this bug. Needs a real answer, not a tooltip. TestSuiteList.jsx:479
Plan-side sign-off
on FR-7 option D		Fixed at intake, but it assumes the plan owner accepts that a copy counts as an update. If they refuse, a dropped-config notice returns and every dialog here gets taller.
Copy of an
unrunnable suite		A suite holding non-Chrome browsers on a plan without cross-browser cannot run, and the checkboxes that would fix it are disabled by the same flag. The copy inherits that dead end. B draws a warning for it by reusing the shipped tooltip; A and C stay silent. The PRD leaves this unowned.
